Strata · privacy and activity logging

Before you continue

This dashboard is for managing Strata and its hosted services. To protect those services and support accountability, it records dashboard account activity and operational events.

  • Account data: username, e-mail address, account permissions, storage zones, sign-in times and whether e-mail verification and this notice were completed.
  • Security and audit events: timestamp, source IP, account, sign-in successes or failures, page/view opened, named dashboard action, UI field identifier changed (never its value), modal opened or closed, affected path or setting, and whether the action succeeded. Account activity records are append-only through the dashboard.
  • Operational and website logs: server errors and service health, plus website request paths, status, timing, bytes, IP/country, user-agent and referrer when those are present in the configured Caddy access log. These can include personal data in request paths or referrers.
  • Authentication secrets: passwords are stored as salted password hashes; e-mail one-time codes are short-lived and stored as keyed hashes. Passwords, one-time codes, editor contents, clipboard contents and form values are not included in dashboard activity events.
  • Purpose and access: root/admin operators can inspect account, audit and operational records. Staff permissions limit dashboard views and assigned storage zones. The dashboard uses the configured Resend account to deliver login codes and invitations.
  • Retention: the append-only account activity ledger is retained in the instance database without an in-dashboard deletion control. Website request retention follows the configured raw and aggregate retention periods; rotated Strata process logs are kept in a bounded set of files.

Do not use this system if you do not agree. Ask the Strata root administrator about access, correction or retention questions.
