# Security, reliability and experience audit — 15 October 2026

The audit found and fixed permission bypasses, filesystem escapes, authentication races, upload corruption and several interface failures. The original regression suites passed before these changes, which made additional negative and concurrency tests necessary. Existing local work was preserved.

## Findings and fixes

Severity describes the potential impact with the prerequisites in the second column. These are findings in Strata's own code and configuration; the dependency finding is separately attributed to upstream.

| Finding | Impact and prerequisites | Fix |
| --- | --- | --- |
| **High — arbitrary storage roots bypassed owner privileges** | An administrator with drive management could mount Strata's source or other host folders and then read or edit them through Files, despite lacking `code.write` or access to the secrets editor. | Non-owners can create file/page drives only inside configured or existing storage roots, checked after resolving links. The owner and owner-issued API keys can approve new roots. HTTP and isolated regressions verify rejection of the source tree and continued access to approved storage. |
| **High — first-run setup accepted attacker hostnames** | On an instance with no owner, a DNS-rebound browser origin could address loopback, read the setup key and submit a same-origin owner-creation form. Checking only the client IP and Origin/Host equality was insufficient. | First-run access now requires a loopback client and a localhost/loopback Host. Tests cover both reading setup and submitting an otherwise valid owner form using an attacker hostname. |
| **High — public Transform/Media paths could follow filesystem links** | A symlink or Windows junction inside a served folder could expose files outside the drive, or alias a hidden/protected folder under a public name. A filesystem link must already exist; ordinary HTTP uploads do not create one. | Public resolution checks the canonical filesystem path and rejects linked aliases. Preview folder enumeration skips links. Tests exercise real Windows junctions to external and hidden directories. |
| **High — recursive ZIP/copy escaped the selected tree** | A nested file symlink or Windows junction could cause ZIP downloads or copy jobs to read outside the selected folder. | Recursive exports skip symbolic links and reparse points, omit managed storage folders, and revalidate paths before reading/writing. Tests confirm that ordinary files survive while linked content is excluded. |
| **High — storage-zone aliases bypassed path permissions** | A link inside an allowed zone could point to a different zone on the same drive. The drive boundary check passed while the zone check used only the requested spelling. | File authorization now requires permission for both the requested and canonical paths. A junction-based regression verifies denial. |
| **Medium — analytics-only accounts received visitor details** | `analytics.read` allowed `/api/stats`, `/api/insights` and `/api/live`, whose responses included IP lists, scanners, heaviest clients or raw recent requests. `/api/requests` alone was correctly restricted. | Visitor-detail fields are empty unless the caller holds `analytics.visitors`, including raw and rollup statistics. The UI hides client/scanner views without that permission, and request polling checks the correct capability. |
| **Medium — unsafe HTTP body framing** | Negative Content-Length values could reach Python reads with “read to EOF” semantics. Duplicate lengths and Transfer-Encoding/Content-Length combinations were ambiguous. Malformed or oversized sign-in forms could escape the normal API error handler. | A shared framing validator rejects negative, duplicate, invalid and ambiguous lengths. Chunked uploads validate sizes, terminators, trailer limits and total bytes. JSON requests require objects. Form errors produce handled responses, and dashboard sockets have an idle timeout. |
| **Medium — accepted chunks could be corrupted by failed retries** | A retry overwrote the assembly file before checksum verification. Failure left the previous receipt marked as accepted. Chunked requests with a misleading Content-Length could also overwrite adjacent chunk bytes. | Incoming chunks are staged and fully validated before committing. Writes, receipts, completion and cancellation are serialized per upload. Resumable chunks require their exact declared length and reject Transfer-Encoding. |
| **Medium — resumable uploads ignored the configured file-size limit** | Chunk initialization allowed sizes up to 16 TiB even though remote fetches used `upload_max_bytes` (20 GiB by default). | Single, resumable and remote uploads use the same configured limit. Resumable uploads reject oversized files before creating the temporary file. |
| **Medium — single-use credentials had concurrency races** | Concurrent successful email-code checks or invite/reset redemptions could read the same unconsumed record before either request deleted it. Authenticator/recovery checks also lacked a shared critical section. | Email codes are checked/consumed in an immediate SQLite transaction. Invite/reset redemption atomically claims the live token in the password-update transaction. Authenticator/recovery checks are serialized. Concurrency tests verify exactly one successful email-code and invite redemption. |
| **Medium — mixed-case session revocation was incomplete** | Account lookup was case-insensitive while in-memory and persisted session revocation compared usernames case-sensitively. | Successful login uses the canonical stored username; both session stores revoke case-insensitively. |
| **Medium — malformed referrers could discard a traffic batch** | A client-controlled malformed URL such as `Referer: http://[` could raise during log parsing. The exception discarded the surrounding batch after advancing the read offset. | Invalid referrers become empty strings. Other malformed records are isolated so valid neighboring requests continue into storage and live statistics. |
| **High, conditional — dependency minimum admitted vulnerable Pillow releases** | `Pillow>=11.0` permitted releases affected by upstream image-parser/memory-safety advisories. The installed runtime was already 12.3.0; this was a supported-version and upgrade-path gap. | The minimum is now 12.3.0. Setup checks installed package versions against requirements, including an existing vendor installation, rather than checking only whether modules exist. Tests reject old and prerelease Pillow versions and accept 12.3.0. |
| **Low — missing tunnel configuration produced HTTP 500** | Opening Network on an unconfigured instance failed `/api/network/ingress`. | The API returns an explicit unavailable state with an actionable message. The UI presents that state, and write attempts receive a configuration error. |
| **Low — upload cancellation raced initialization and retries** | Cancelling while initialization was pending could leave a server session behind. Delayed retries could requeue cancelled work, and responses from an expired chunk session could mutate a replacement session. | Cancelled initialization aborts its newly returned session, stale callbacks are ignored, retries respect cancellation/session identity, and upload-slot accounting uses `finally`. Browser regressions cover all three races. |
| **Low — keyboard and connection-state rough edges** | Tab could leave a modal, sheet closure lost focus, `/` could access a missing filter field, and network errors could leave the connection indicator displaying “live”. Blocked sessionStorage could also interrupt boot with a saved landing view. | Dialogs have accessible names, focus wraps inside active modals and returns after closing a sheet, shortcuts check their target, storage access is guarded, and the connection indicator reflects failure/recovery. |
| **Low — documentation and test-reporting defects** | README contained unresolved merge markers. Security instructions described the old secret location. The harness hid integration-test skips. Starting a second demo could falsely detect the first server as its own. | Merge markers were removed, secret/upgrade guidance was corrected, skips are printed, and the demo checks its ports before starting. |

## Validation

- `python tests/audit_test.py`: **18 isolated regressions passed**, including actual Windows junctions, concurrent code/token redemption, upload corruption attempts and storage-root restrictions. No symlink/junction tests were skipped in the final run.
- `python tests/run_all.py --offline`: the full disposable-instance harness passed, covering first-run setup, SMTP, security, audit regressions, bot configuration/install behavior, permissions, Team, sign-in, installer, automatic bans, secrets, the available local extension and media unit tests. The Caddy integration skips described below are printed explicitly.
- `python tests/ssrf_test.py <throwaway-home>`: public HTTPS succeeded with certificate verification; loopback, LAN, cloud metadata, IPv6 loopback and a hostname resolving to loopback were refused.
- `node tests/browser_smoke.mjs <isolated-demo> <screenshot-directory>`: **27 views × two sizes = 54 view checks**, at 1600 × 1000 and 390 × 844. No uncaught browser exceptions, failing local HTTP responses or page-wide horizontal overflow. Internal file-table scrolling remains available on small screens.
- Browser checks also passed modal Tab/Shift+Tab wrapping and focus restoration, the `/` shortcut in Settings, three upload cancellation/stale-response scenarios, and connection failure/recovery.
- Python undefined-name checks, JavaScript syntax checks and `git diff --check` passed.

The browser used a fresh headless Edge profile and a separate disposable demo on port 8292. It did not use or modify the existing demo on port 8290. Screenshots and the machine-readable browser results were saved outside the repository in the chat's visualization directory.

## Deployment notes and validation limits

1. Restart Strata and its Transform/Media helpers to load the Python changes. Refresh dashboard tabs to load the JavaScript changes. On older installations, rerun `python setup.py` and accept the package update so the dependency requirement is applied to the deployed runtime.
2. Adding an entirely new storage root now requires the owner. Administrators can continue managing drives within configured or existing storage roots. Existing drive roots remain trusted; review any roots that were created by non-owner administrators before this change.
3. Recursive exports omit filesystem links and junctions. Public Transform/Media requests through linked aliases are refused. Applications intentionally relying on those aliases should use a direct drive mapping approved by the owner.
4. Chunk validation temporarily stages each in-flight chunk on the host's temporary volume before writing it to the destination. This preserves parallel network transfers while serializing commits; allow temporary space for the configured number and size of parallel chunks.
5. Caddy, cloudflared and Anubis executables were unavailable in this environment. Real `caddy validate`, requests through a real Caddy and real Anubis puzzle integration were therefore not exercised. The harness's Caddy stub and bot policy/install tests passed. Run the existing suites with `STRATA_CADDY` and `STRATA_ANUBIS` on the deployment host before release.
6. The audit ran on Windows/Python 3.12. Linux path comparisons were corrected to preserve case sensitivity, but the full suite was not run on a Linux host in this session. Actual Cloudflare changes, mail-provider delivery, tunnel restarts and production deployment were not performed.

This is a bounded source and behavior audit with verified fixes, not a claim that every possible vulnerability has been eliminated.

## Dependency evidence

The minimum-version change was checked against the maintainers' advisories, including [PSD out-of-bounds writes](https://github.com/python-pillow/Pillow/security/advisories/GHSA-cfh3-3jmp-rvhc), [unchecked GD image allocation](https://github.com/python-pillow/Pillow/security/advisories/GHSA-phj9-mv4w-65pm), [coordinate-overflow memory corruption](https://github.com/python-pillow/Pillow/security/advisories/GHSA-6r8x-57c9-28j4) and [ImageCms output-mode memory corruption](https://github.com/python-pillow/Pillow/security/advisories/GHSA-9hw9-ch79-4vh6). The July advisories identify 12.3.0 as patched. These establish the dependency floor; each advisory's reachability and prerequisites differ, and this audit does not claim every upstream issue is directly exploitable through Strata.
